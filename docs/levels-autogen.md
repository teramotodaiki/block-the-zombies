# レベル自動生成方針

## ゴール

- Codex / AI コーディングに、レベル TS ファイルを自動生成・修正させる。
- 仕様を守ったレベルが量産できるようにする。
- 生成後に最低限のバリデーションを自動で行う。

## 入力パラメータの例

- 難易度の目安（例：very-easy / easy / normal）。
- 使用バイオーム（例：plains / desert）。
- 使用する要素：
  - マグマあり／なし
  - ゾンビの数
  - ブロック上限値の範囲
- やってほしいことの例：
  - 村人が「それなりに遠回りする」ルート
  - ゾンビとのニアミスが何回か起きる など

理由：
- 人間がざっくりとした「遊ばせ方」を指定し、
  細部を AI に任せられるようにするため。

## 禁止事項（生成時に守るべきルール）

- 村人が 1 人もゴールできない構造（明らかな詰み）を作らない。
- スタート直後に村人が即マグマ落下・ゾンビ接触する構造を避ける。
- ブロックを一切置かなくてもクリアできるレベルは、原則として作らない
  （例外を設けるなら「チュートリアル用」として明示する）。

理由：
- 生成レベルの品質を最低限保証し、人間によるチェックコストを減らすため。

## バリデーションの期待値（抽象）

- レベル定義が TypeScript の型を満たすこと。
- シミュレーションをざっくり数秒回し、
  - 村人が 1 人もゴールしない
  - 村人がスタート直後に全滅する
  などの極端な状態を検出する簡易チェックを行う（詳細はテスト仕様で補足）。

理由：
- レベル数が増えると人力チェックが現実的でなくなるため。
- ロジック変更に伴う破壊的変更を検知するため。
