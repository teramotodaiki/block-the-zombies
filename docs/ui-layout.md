# 画面構成・UI レイアウト仕様

## 共通ルール

- 画面内にはテキスト・数字を描画しない。
- UI は主に画面上部の HUD バーに集約する。
- フィールド部分（タイルを置く範囲）は画面中央〜下側に広く確保する。
- ブラウザのアドレスバーや Android ナビバーを考慮し、
  画面下端付近には重要 UI を置かない。
- UI はすべて Phaser で作成する。

理由：
- タブレット環境で誤タップによる OS UI 呼び出しと混ざるのを避けるため。
- 子どもが UI を見失いにくいよう、上部にまとめておくため。

## ゲーム画面の HUD 構成

画面上端中央に HUD バーを配置する。

- 左側：
  - ホームボタン： タイトルへ戻る（ポーズ中のみ有効）。
  - リトライボタン： 最初からやり直す（ポーズ中のみ有効）。
- 中央：
  - ポーズボタン： プレイ中は一時停止、ポーズ中は再開。
- 右側：
  - ブロック残量： ブロックアイコン ＋ 数字（残り個数）。

### ホーム・リスタート・ポーズ

- プレイ中の誤操作を防ぐため、ホーム遷移やリスタートボタンは **ポーズ中のみ有効** とする（半透明表示などで区別）。
- ポーズメニュー（オーバーレイ）は廃止し、HUD 上で完結させる。

## タイトル・マップ・クリア画面

- タイトル
  - 背景に動画（`title_bg.mp4`）をループ再生。
  - 画面全体をタップしてスタート。ボタンやロゴ画像は配置しない。
- バイオーム選択（TBD: 今回は実装省略、LevelSelectSceneへ統合）
- レベル選択
  - ステージノードを並べる。
  - 未開放レベルは鍵アイコンでロック表示。
  - クリア済み・開放済みレベルは選択可能。

- クリア画面
  - バックのゲーム画面を暗くして、その上にオーバーレイ。
  - 「LEVEL CLEAR」の文字とアクションボタン。
  - 「Next」ボタン： レベル選択画面へ戻る（次のレベルがアンロックされる）。
  - ホームやリトライが必要な場合は、プレイ中のポーズメニューを使用する（クリア後はNextのみでシンプルに）。
