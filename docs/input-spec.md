# 入力・操作仕様

## 入力デバイス

- タッチ操作（タブレット・スマホ）。
- マウスクリック（PC）の場合もタップとして扱う。

## 基本ルール

- 画面内のどこをタップしたかで挙動を変える。
  - 上部 HUD 領域：UI ボタン（ホーム／リスタート／ポーズ）。
  - ゲームフィールド領域：ブロックの設置／破壊。
- 長押しは、誤タップ防止したいボタン（ホーム・リスタートなど）に限定して使う。
  - HUD（UI）とフィールドのタップ判定が重ならないよう、HUD への入力を優先する。

理由：
- 子どもが直感的に理解しやすい操作体系にするため。
- 不要に複雑なジェスチャー（スワイプ等）は避けるため。

## ブロック操作

- ゲームフィールド部分をタップ：
  - その位置をグリッド座標に変換し、
    core に「そのマスをトグル（置く／壊す）」するよう指示する。
  - 実際に置けるかどうかの判定は core 側で行う。
- タップしたが置けない場合：
  - 視覚的フィードバック（マスを一瞬赤く光らせるなど）。
  - 短い「コツン」とした SE を鳴らし、「無効操作」であることを伝える。

理由：
- 置ける／置けないの条件はレベルやルールに依存するため、
  core に集約して管理するため。
- プレイヤーが「反応がない」のではなく「置けない」ということを認識できるようにするため。

## UI ボタン

- ホームボタン：
  - 長押し（一定時間押し続けたら実行）を採用する。
- リスタートボタン：
  - 同上。誤タップで即リセットしないようにする。
  - ポーズ状態ではフィールドへのタップは無効化する。
- ポーズボタン：
  - ワンタップでポーズオーバーレイを出す。

理由：
- ホーム・リスタートは「誤タップで失われるコスト」が大きいため、
  明示的な操作のみ受け付けるようにするため。
- ポーズは誤タップしてもそこまで致命的ではないため、
  操作の簡単さを優先するため。
